# 架构建议补充（产品负责人，2026-11-23）

> 原文记录，作为设计评审时的重点检查项。

1. **提醒一定要由 NAS 后端负责。**
   例如每半年续费一次 eSIM，即使电脑关机，NAS 也应该能在指定日期触发提醒。所以提醒调度要放在 FastAPI 后端，而不是简单调用 Windows 定时器。

2. **重复任务要区分系列和发生实例。**

   ```text
   每半年续费 eSIM
   1. 11月24日      已完成（本次完成记录）
   2. 2027年5月24日  待办
   3. 2027年11月24日 未来
   ```

   整个系列仍然对应一条极空间原生笔记，每次完成记录单独管理。

3. **不要让极空间原生笔记变成只有自制软件能读懂的黑盒。**
   任务标题和备注尽量保持正常可读的 HTML 正文，结构化元数据要有明确格式和兼容性测试。尤其是官方记事本修改后，不能把提醒、重复规则等信息弄丢。

建议：先重新设计数据模型和交互原型，不要马上写代码。这个项目真正的难点不是 Todo 列表，而是**原生笔记兼容性、重复任务引擎和跨设备提醒机制**。
